# 电商订单与支付微服务架构（Filesystem MCP 演示样例）

## 核心服务
- **API 网关（Gateway）**：统一鉴权、限流与路由转发，接收 Web/App 端请求。
- **订单服务（Order Service）**：创建订单、管理订单状态机（待支付 → 已支付 → 已发货 → 已完成）。
- **库存服务（Inventory Service）**：基于 Redis 分布式锁执行预扣库存与超时释放。
- **支付服务（Payment Service）**：对接支付宝/微信支付回调，校验签名并更新支付流水。
- **消息队列（Kafka）**：异步解耦订单创建、支付成功与物流通知事件。
- **通知服务（Notification Service）**：消费 Kafka 事件，推送站内信与短信通知。

## 数据流向
1. 用户提交订单请求 → API 网关 → 订单服务。
2. 订单服务调用库存服务预扣库存，并将订单写入 MySQL。
3. 用户发起支付 → 支付服务完成第三方渠道扣款 → 发送“支付成功”事件到 Kafka。
4. 订单服务消费事件并更新状态为“已支付”，同时通知服务发送下单成功提醒。
